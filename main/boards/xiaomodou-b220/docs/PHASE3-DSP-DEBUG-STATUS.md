# Phase 3（ZL38063 音频）调试状态 —— 续接文档

> 最后更新：2026-10-07 15:5x，对应固件 `xiaozhi.bin` 2356.7 KB（含 GPIO19 取证 + HBI 诊断）

## 1. 一句话现状

屏幕/背光/WiFi/PSRAM/CPU 全部正常（Phase 2 已通关）；**音频卡在"ZL38063 完全不应答 HBI"**：
所有寄存器读回 `0x0000`，`reg 0x34` 读不到 `0xD3D3`，host-boot 因此中止。
**软件侧已排查完毕、无问题**；剩余疑点全部指向硬件电气层（复位网络/片选网络）。

## 2. 已经**排除**的可能（都有证据，别重复查）

| 假设 | 结论 | 证据 |
|---|---|---|
| HBI 帧格式/字节序错 | ❌ 排除 | 逐位对照 ADF 参考实现：5 个代表性操作（读 `0x0034`/`0x0030`、写 `0x0014`/`0x012C`/`0x0200`）的命令字、页选、数据字**全部一致**；双向字节交换、一次 CS 一个字、MSB-first、CS 由 SPI 驱动托管、10 MHz/mode 0/DMA 处理均一致。且 `0xD3D3` 是字节序回文，交换写反也会读出它，而我们读到 `0x0000` |
| 缺"上电使能"步骤（原厂在复位 DSP 前调了三个函数） | ❌ 排除 | `0x40203350` = `xTimerStop`×2（纯软件）；`0x40124ce8` = `gpio_set_intr_type(38,0)`（GPIO38 是输入中断线，很可能是底座通信线）；`0x40207ae8` = **`audio_pa_on`**（AW9106 `0x5B` 寄存器 `0x02`，只影响功放出不出声，与 HBI 无关） |
| 配置记录"门控" | ❌ 不存在 | `VprocTwolfLoadConfig` 循环里只有一个分支（回循环头），**260 条全写** |
| DSP 固件镜像缺失 | ❌ 已找到 | DROM `0x3f4322e4`，步长 **44** 字节 × 3699 条 = 118,244 B 载荷；数组末尾正好等于配置记录长度字段（交叉验证通过）。原厂**每次上电都 host-boot**（`reg 0x14←1` 会强制 boot ROM，自启动被覆盖） |
| DSP 不存在 | ❌ 存在 | 用户示波器实测原厂机 **I2S_WSA = 48 kHz**（说明原厂成功启动并让 DSP 驱动 I2S） |

## 3. 当前唯一疑点（电气层）

**已排除：复位网络。** 用户示波器实测（原厂机）GPIO19：电源开关关时**低**，按下开机后**拉高并一直保持高**
⇒ 复位脚正常释放，DSP 不是被复位按住的。（注意：此前我们固件里 `gpio_get_level(19)` 读回 0，
与之一致的解释是**断电/开关未开时该网络本来就低**，或者那次读发生在异常状态下；结论以示波器为准。）

**剩下的两种可能**：
1. **DSP 没通电**（某个使能/供电我们没打开，例如底座握手后才上电）；
2. **HBI 片选/引脚不通**（`GPIO0` 既是 DSP 片选又是启动 strapping 脚，这条网络上有 USB 桥）。

**区分方法（关键一步）**：在**跑小智固件的开发机**上量 **GPIO25（I2S WS）**：
- 无波形/0 Hz → DSP 没在运行（供电/使能问题）
- **48 kHz** → DSP 正在运行 ⇒ 问题纯在 HBI 的片选/引脚
同时可量 **GPIO0** 空闲电平（应为高）与通信瞬间是否拉低。

## 4. 待做的两件事（任选其一即可定案）

**方案 A（推荐，示波器，5 分钟）**：断电重上电时看
- **GPIO19**：应为「约 1.2 s 处低 10 ms → 随后保持高」。一直低 = 被外部按住。
- **GPIO0**：空闲应为高，仅通信瞬间拉低。一直低 = 片选被占住。
- 可选 **GPIO34(MISO)**：通信时应有数据跳变，恒 0/恒高 = DSP 完全没驱动。

**方案 B（纯软件）**：刷当前这版取证固件，看日志
- `GPIO19 output, no pulls, driven HIGH -> read ?`：**必须是 1**
- `GPIO19 input, internal pull-up      -> read ?`：**0 = 有强下拉或另一驱动器**
- 以及 `AW9106 reg 0x02 <- 0x3F` 后 `app status` 是否变化

## 5. 方向明确后，下一版固件要一次做掉的三件事

1. **照抄原厂 6 次重试**：原厂 `0x40124454` = 复位脉冲 → 500 ms → 最多 6 次调用 `0x40126240(mode 0)`；我们目前只试 1 次。
2. **播放前开功放**：I2C 写 `AW9106 0x5B: reg 0x02 ← 0x02`（`0x00` = 静音）。这是 RE 确认的 `audio_pa_on`，**出声必做**。
3. 按电气测量结论修正复位/片选处理（例如：若 GPIO19 被底座按住 → 需要先实现底座 `{AT+...}` 握手；GPIO38 中断线是底座通信的新线索）。

之后才轮到 **I2S 48 kHz 全双工**（BCK5/WS25/DO26/DI35）+ 麦克风→喇叭回环。
